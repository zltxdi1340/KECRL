# KECRL 首轮实现准备计划

> 日期：2026-09-29。最新状态：首批 Python 标准库类型与接口骨架已创建；下文工程建议与功能验收范围并未全部实现，不构成理论结论、实验方案或最终工程架构。

## 1. 首轮目标

首轮只验证三项接口契约能否保持两库边界和运行时信息流：

```text
RetrieveMechanisms -> RequestImplementation -> ExecuteImplementation
                         |                         |
                  Skill Library             TransitionResult
                         |                         |
                  Module/SPI feedback     Knowledge Evidence / Skill feedback
```

首轮不实现完整 Knowledge Evolution、FOMAML、环境搜索、正式 Policy 训练或实验统计。

## 2. 建议的临时技术选择

| 项目 | 首轮建议 | 状态与边界 |
|---|---|---|
| 实现语言 | Python | 工程建议，未冻结；不代表最终 Policy 后端 |
| 数据表示 | 先使用显式、可检查的结构化对象与不可变任务视图 | 只表达契约字段，不规定数据库或序列化格式 |
| 存储 | 先使用进程内 Knowledge Bank / Skill Library 适配器 | 仅用于契约验证，不作为长期存储方案结论 |
| 环境 | 受控的最小模拟适配器或纯接口替身 | 不是正式实验环境，不写入实验结论 |
| Policy | 可替换的执行端接口；首轮允许受控占位实现 | 占位实现不得伪造资格或研究结果 |
| 验证 | 结构化输入的契约检查与路径检查 | 不替代训练、基线或统计实验 |
| 依赖 | 仅使用标准库，直到真实算法需要额外依赖 | 依赖清单尚未冻结 |

若后续真实 Policy 或环境需要额外依赖，先记录理由和版本，再更新配置文档；不能因为首轮占位接口而默认为最终方案。

## 3. 首轮最小边界

必须支持：

1. Knowledge Bank 返回范围匹配的 `current + confirmed` 机制，并保留不同 OR 机制。
2. Planner 传递目标、计划输入、`P_start/P_hold`、资源和公开上下文；这些字段不互相替代。
3. Skill Library 依次处理合格 Module 复用、SPI 生成路径和 `unavailable`。
4. 只有资格通过的 Module 才能进入 `ExecuteImplementation`。
5. `TransitionResult` 区分 `true`、`false` 和 `unknown`；声明输出不替代实际检测。
6. 环境证据与技能反馈分开传递，Knowledge Bank 不接收 Policy 参数、梯度、完整轨迹或 Module 性能。
7. 任务视图可追溯到起始 Knowledge/SPT 版本；更新不原地改写既有 Module。

首轮不加入新的长期存储、统一超级状态、额外生命周期状态、自动重试策略、并行调度或未确认的统计方法。

## 4. 功能验收范围

使用受控输入进行以下检查：

| 检查 | 通过条件 |
|---|---|
| 机制检索 | 未确认、不适用机制不进入正向结果；空结果不被解释为不可达 |
| 请求完整性 | 目标、计划条件、保持条件、资源和上下文可被检查 |
| Module 资格 | 未资格通过的 SPI/Policy 不能执行 |
| 结果判定 | 目标只由实际检测确认；未知不转为失败 |
| 两库边界 | Knowledge Evidence 不含技能侧禁止字段；技能反馈不直接改写知识结构 |
| 版本隔离 | SPT 更新或恢复不改写既有 Module；任务起始视图可定位 |
| 反馈分流 | 同一执行结果能分别形成合法环境证据摘要和技能经验入口 |

这些检查只证明接口和边界行为，不能证明知识发现、FOMAML 学习效率或任务性能改善。

## 5. 进入代码阶段的准入条件

开始编写 `src/` 前，应确认：

- 首轮语言和依赖选择接受为工程临时方案；
- `src/skills/` 是否按架构建议创建；
- 受控模拟适配器的范围和占位 Policy 的非研究性质；
- 验收输入是否足以覆盖复用、新建、不可用、未知四条路径；
- 所有运行参数仍从参数清单读取，不在代码中偷偷冻结理论未决数值。

本轮已按用户继续推进的指令创建 `src/skills/` 和最小类型骨架，采用 Python 标准库，并加入构造时一致性校验、受控内存适配器、任务版本视图、最小运行闭环及知识证据禁止字段校验；运行时成功、失败和未知结果分别映射到既有四类任务结果，且仍保持 `unknown` 证据语义，需独立 Knowledge Evolution 验证后才能计入统计。适配器只支持预置数据，不执行学习或持久化。技能反馈仅保留标识和执行摘要。后续按本节边界逐项落实，不将单次闭环检查解释为算法或实验通过。

2026-10-01 补充：`InMemorySkillLibrary` 已增加最小实现契约兼容性检查。请求必须满足实现声明的适用范围、启动能力、可比较资源上限和请求上下文中的实现约束；保持能力仍保留给执行期间检查。任一检查不通过均返回既有 `unavailable`，不生成新的状态或实现对象。

当前限制：校验只覆盖明显自相矛盾的构造输入；类型注解不执行完整运行时校验，`frozen=True` 不会冻结字段内的嵌套 Mapping。内存适配器不代表持久化实现。现有机制类型尚未覆盖生命周期/历史字段，SPT/SPI/Module 对象与任务版本视图也未实现。基类接口方法仍抛出 `NotImplementedError`，不会伪造执行成功或资格结果；运行闭环不会执行真实学习。
