# 理论设计原则与复杂度收敛决策

> 日期：2026-09-21  
> 状态：已确认  
> 适用范围：KECRL 第一篇工作，数学建模阶段

## 1. 背景

项目在完成 Knowledge、Module、SPT、SPI 和 Skill Evolution 的初步形式化后，部分章节同时写入了核心算法、统计保证、工程防护和未来扩展。这样虽然覆盖面较广，但会增加实现成本，模糊科学贡献，也使尚未决定的内容看起来像最终规范。

本次决策确定理论设计应保持最小充分性，并对既有内容进行收敛。历史决策文件继续保留其当时的讨论记录；本决策和更新后的 PROJECT_BIBLE 是当前正式规范。

## 2. 已确认设计原则

1. **最小充分性**：只保留回答科学问题、保证接口语义或使主算法可实现所必需的定义与规则。
2. **科学贡献优先**：优先表达 Knowledge/Skill 分离、Capability 契约和两类演化的核心机制，不把通用工程能力包装成理论贡献。
3. **核心与防护分离**：核心理论、实现防护和未来扩展分开记录；防护可以存在，但不必全部进入数学主线。
4. **每个问题一个主方法**：第一篇工作为每个主要问题选择一个可实现的主算法，替代方案只保留选择理由和适用边界。
5. **超参数不等于理论**：样本数、置信水平、阈值、缓冲区容量和更新频率保留为实验设置，除非它们直接决定语义正确性。
6. **封闭假设优先**：第一篇工作在受控、有限、可验证的假设下完成，不提前解决开放世界和所有异常情况。
7. **数学服务于理解**：公式用于明确对象、输入、输出和更新关系，不为每个程序字段建立同等复杂的数学结构。
8. **按必要性增加复杂度**：只有在正确性、可实现性或核心评价确实需要时，才增加状态、统计量、约束或流程。

## 3. 审计结论

Knowledge Evolution 的主要结构（Capability Schema 冻结、机制表示、AND/OR、硬可达性与成本分离、验证调度、Refine、Merge、Retire、Retrieve 和 `knowledge_gap`）直接承担项目语义，应保留。

Skill Evolution 的部分实现保护超出了当前科学问题所需的最小范围，主要包括：正式兼容组对象、五类资格结果、Wilson 区间写入核心规范、细粒度分层证书、Meta-Buffer 采样机制、provisional/quarantine 生命周期和完整回滚状态机，以及 Reptile 的正式公式。这些内容不再作为第一篇工作的核心数学要求。

## 4. 收敛后的正式范围

- 保留 SPT、SPI、Module 的定义及其职责边界。
- Skill Evolution 只指定上下文条件化 FOMAML、support/query 分离、跨 SPI 反馈、独立 Module 资格判断和新旧 SPT 的独立比较。
- Module 资格采用“证据充分且达到成功与契约门槛”的最小规则；样本数、置信方法和阈值为实验设置。
- SPT 候选只有在公平、独立的验证中改善未来 SPI 学习效率且不造成不可接受退化时接受；否则保留当前版本。旧版本保留用于恢复，但不建立额外生命周期状态机。
- 训练数据与评价数据必须分离；具体数据角色、采样配额和版本追踪属于实现防护。
- Reptile、复杂置信序列、细粒度回滚检测和异构适配保留为备选或未来工作。

## 5. 影响

- PROJECT_BIBLE 第 9 节收敛为可直接实现的最小 Skill Evolution 规范。
- ROADMAP 只记录研究阶段和当前未决问题，不再暗示已确定完整工程生命周期。
- ARCHITECTURE 增加最小充分设计要求，指导后续理论与实现审查。
- 历史决策文件不改写；如需更强统计保证或更复杂生命周期，另立决策并明确其非核心性质。
