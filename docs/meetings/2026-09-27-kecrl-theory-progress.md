## 1. 一句话进展

KECRL 已从概念框架推进到可实现的分层数学体系：Knowledge Evolution 负责持续修正环境机制，Skill Evolution 负责通过跨 SPI 元学习提升未来技能获取效率，二者通过任务层规划协同，但长期记忆和更新证据严格分离。

## 2. 本阶段解决的问题

本阶段依次完成了七项工作：

1. 正式定义 Module 及其实现契约、Policy、经验和资格边界。
2. 区分 SPT、SPI 与 Module，并给出数学和程序语义。
3. 确定 Skill Evolution 主方法为上下文条件化 FOMAML。
4. 确定 Knowledge Evolution 的 Beta-Binomial 更新、单轮预算和确认规则。
5. 确定 Continual Learning Pipeline、双反馈分流和任务边界版本视图。
6. 确定“两个局部演化目标 + 一个任务层耦合评价”的联合目标。
7. 完成整体 KECRL 分层形式化，并限定可证明性质的范围。

## 3. 当前核心框架

### Knowledge Evolution：学习什么

- Capability 是参数化、可检测、Agent 无关的最小环境状态谓词。
- 环境机制为：

  \[
  M=(P_{start},P_{hold},Y).
  \]

- 同一机制内部父条件为 AND，指向同一目标的多条机制为 OR。
- 硬可达性与成本修饰因素分开表示。
- Capability Schema 初始化审核后冻结，在线只更新已有节点之间的机制。
- 机制证据按原子命题维护，状态为 `candidate/testing/confirmed/rejected`，生命周期另行管理。

### Skill Evolution：如何学习

- SPT 是 Skill Family 级共享的技能实例生成器与元学习器。
- SPI 是针对具体参数绑定和状态转移请求产生的学习规格，不是已学成技能。
- Module 是 SPI 经 Policy 学习并通过独立资格检查后形成的可执行单位。
- Skill Evolution 采用上下文条件化 FOMAML，support 用于适应，query 用于元更新。
- SPT 候选只有在未来 SPI 学习效率改善且重要既有 SPI 不发生超限退化时才接受，并保留稳定版本用于恢复。

### 两类演化的协同

Knowledge Bank 回答“哪些状态转移在环境结构上成立”，Skill Library 回答“当前是否有合格实现以及如何学习实现”。运行时由规划层依次调用：

```text
RetrieveMechanisms
-> RequestImplementation
-> ExecuteImplementation
-> 检查实际状态
-> 分流环境证据与技能反馈
```

规划层只保存任务内临时状态，不形成第三个长期知识库。

## 4. 联合目标与整体形式化

不采用复杂统一加权损失，而保留两个局部目标：

\[
J_K(K_t)=Q_{structure}(K_t)-\lambda_K C_K,
\]

\[
J_S(L_t)=
-\mathbb E_I\left[\sum_k\alpha_k\mathcal L_I^{query}(\theta_I^k)\right]
+\lambda_QQ_{module}.
\]

任务层评价二者联合效果：

\[
J_T(K_t,L_t,\Pi)
=\mathbb E_\tau[R(\tau)-\lambda_cC(\tau)-\lambda_uU(\tau)].
\]

整体系统表示为：

\[
\mathfrak K=
(\{\mathcal E_g\}_{g\in\mathcal G},V_0,K_t,L_t,\Pi,U_K,U_S).
\]

其中，\(K_t\) 与 \(L_t\) 独立更新，\(\Pi\) 只在任务层协调。

## 5. 当前能够主张的理论性质

第一篇工作只主张六项有限、条件式保证：

1. Capability Schema 在在线阶段保持不变。
2. Knowledge Bank 与 Skill Library 的长期信息边界保持。
3. 机制调用满足启动与保持条件的一致性检查。
4. 合格 Module 在范围、资源和实际输出满足条件时具有契约组合性。
5. 同一适用范围内的 Bernoulli 证据满足 Beta-Binomial 共轭更新。
6. 在有限预算和正预算消耗下，每轮 Knowledge/Skill 更新有限终止。

当前不声称全局最优、FOMAML 全局收敛、逐任务性能单调提升、有限预算发现全部机制，或在线发现冻结 Schema 之外的新 Capability。

## 6. 设计收敛情况

项目已主动压缩复杂度：

- 每个主要问题只保留一个主方法。
- 阈值、样本数、缓冲区和更新频率作为实验参数，不包装成理论贡献。
- 不构造统一超级 MDP，不增加第三个长期知识库。
- 不为边界情况增加额外状态机。
- 核心理论、工程防护和未来扩展分开记录。

因此，当前框架虽然覆盖完整，但主线仍然是两类演化及其协同，而不是多个算法的堆叠。
