# task7 v6：后半程窗口3倍采样（2026-11-19）

## 问题与结论边界

检验在同一共享3A网络、500次Adam更新与现有七维masked MSE下，仅把示教后半程起点窗口的抽样权重从1改为3，是否提高原22个source开发交接状态的后半程完成数。v5首动作拟合和总成功数下降支持检验优化预算分配，但未证明梯度稀释、空间表征或具体物理机制是主因。

相对时间不等于操作阶段。本轮不读取物体真值或阶段标签，不能事前认定示教前半全是抓取、后半全是放置；即使改善，也只支持该采样分布在本冻结范围内有用。

## 唯一变量与精确定义

两臂 `uniform_shared_3a` / `late_half_x3_shared_3a` 直接复用未改动的v3共享3A策略：冻结ResNet18 `[512,4,4]`，共享读出512→256、SpatialSoftmax τ=1、坐标MLP 512→1408→128，268维内部零XYZ。两臂可训练参数均**1,499,144**，含骨干总参数12,675,656；完整初始state_dict及trainable mask相同，无未来动作头、无新传感器。

令 N 为示教原始 `actions.shape[0]`，有效因果动作索引为1..N−1。每窗口起点s=1,11,21,…，有效长度min(10,N−s)。只按窗口起点定义后半程：**2s≥N**，等号纳入后半程。

- 控制：432个窗口均权重1。
- 候选：起点2s≥N权重3，其余1；跨中点的窗口只按起点归类，不拆分，不按中心/终点重分类。
- 全部窗口统一归一化，有放回，每更新8抽；不按demo另归一化。不同demo的实际抽样量、有效帧数与时间四分位覆盖都记录。
- 既有审计元数据为30示教N=120..197、432窗口/4188有效当前动作。前半223、后半209，总候选权重850（223+3×209），后半窗口概率从209/432=48.3796%变为627/850=73.7647%。

每模型4000抽的后半窗口期望数为1935.19→2950.59；这是抽样次数，**不是**把500更新拆成若干纯抓取/放置更新。跨中点和末端padding意味着窗口占比也不等于有效帧占比，须报告实际分布。采样变化会改变有效训练目标分布及部分demo质量占比，不能称两臂有效目标完全相同。

## 无浮点CDF歧义的固定采样器

整数权重累计到W；每步本地 `torch.randint(W,(8,),generator=...)` 得到8个整数ticket，用右侧二分找到累计权重区间。概率精确为w/W，不用浮点舍入决定边界。控制W=432、权重全1，映射即原窗口下标，因此沿用旧v3的全部uniform批次。

两臂分别创建局部Generator，初始seed均为训练seed+70777（即旧seed+7×10000+777），不改全局RNG。对象独立、起始seed相同，不声称统计独立；不再要求批次相等。逐更新保留ticket、窗口ID、采样hash和有效帧四分位分布；独立审计用自己的整数累计/线性区间公式重算，不调用生产采样器。

采样器仅接受demo ID、窗口起点/有效长度、原示教动作长度。N与窗口表来自已审计训练JSON，真实执行时再与既有dataset索引核对；不为定权重重读HDF5，不读RGB、动作值、初态或私有状态，不新增网络前向。特征缓存仍只构造一次供两臂使用。
