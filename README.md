
## KECRL

Minimal CPU smoke and server GPU workflow. The smoke configuration is deliberately a controlled interface validation, not a research result.

```powershell
python -m experiments.run --config configs/smoke_cpu.yaml
python -m experiments.evaluate results/smoke/result.json
python scripts/check_environment.py
```

On a GPU server, install the environment-specific framework separately, run `python scripts/check_environment.py`, then use `configs/server_gpu.yaml`. `device: cuda` fails explicitly when CUDA is unavailable; `device: auto` selects CUDA only when available. Results contain configuration, seed, runtime metadata, JSON and CSV summaries. Formal environment, baseline, metrics and training budgets remain experiment decisions and must be recorded before formal runs.

## Current research direction (2026-10-20)

The repository now follows a staged validation route:

1. **LIBERO** for same-family SPT/SPI instance transfer and meta-learning efficiency;
2. **Continual World** for sequential task streams, forward transfer and forgetting;
3. **Crafter** for long-term memory, exploration and Knowledge Evolution;
4. **RoboCasa365** for the final controlled Knowledge--Skill joint evaluation.

The detailed Chinese route is recorded in [the research roadmap](docs/research-roadmap-2026-10-20.md). The LIBERO installation, pinned dataset audit, and KECRL adapter smoke are recorded in [the environment feasibility note](docs/libero-environment-feasibility-2026-10-21.md); the candidate Skill Family, trajectory structure, leakage-audited task/data roles, CUDA runtime, executable BC/SPT/SPI path, first source-SPI learning result, and closed-loop attribution are recorded in [the spatial family audit](docs/libero-spatial-skill-family-audit-2026-10-21.md), [the demonstration phase audit](docs/libero-demonstration-phase-structure-audit-2026-10-21.md), [the transfer split](docs/libero-spatial-transfer-split-2026-10-21.md), [the CUDA smoke](docs/libero-cuda-training-path-smoke-2026-10-21.md), [the BC Policy pipeline check](docs/libero-bc-policy-pipeline-check-2026-10-21.md), [the single-SPI BC diagnostic](docs/libero-single-spi-bc-learnability-diagnostic-2026-10-21.md), and [the closed-loop attribution](docs/libero-bc-closed-loop-attribution-2026-10-21.md). The attribution found that stored same-index observations occur after their paired actions. The matched 500-update same-index/causal pre-action comparison, frozen-weight recurrent-state follow-up, six-start paired action/state divergence trace, 41-point one-step counterfactual trace, controlled state-distribution-shift trace, RGB/proprioceptive modality decomposition, agentview/eye-in-hand camera decomposition, three-seed camera replication, fixed-budget eye-in-hand translation robustness pilot, fixed expert-state synthetic eye-in-hand sensitivity diagnostic, expert-state/free-run alignment diagnostic, action-head representation diagnostic, source-SPI conditional coverage audit, source-SPI stratified error diagnostic, expert replay consistency audit, HDF5—current replay state alignment audit, replay semantics audit, current-runtime replay audit, and replay input alignment audit are complete. The fixed task-3/task-7 Policy input-replacement sensitivity audit then measured historical-causal versus current-runtime observations on four source demonstrations: shared-hidden action MAE was 0.02185 over 456 steps, with six gripper sign flips, and independent recurrent branches increased action MAE to 0.03544. The input replacement changes Policy outputs but does not explain all failures; these remain mechanism diagnostics rather than a formal SPI or Module result. The full source-support replay feasibility audit then found only 17/150 meta-support demonstrations with complete current-runtime action-prefix coverage (mean coverage 0.8735), so HDF5 causal inputs are frozen as the complete offline BC protocol and current-runtime inputs are restricted to closed-loop/alignment diagnostics. The one-step trace reproduced every expert pre-action observation exactly and measured immediate action-to-state effects; the state-shift trace found a larger short-horizon observation-state contribution than hidden-state contribution, and the camera trace consistently found eye-in-hand contribution larger than agentview across seeds. The translation pilot improved closed-loop success in one seed but did not produce a stable cross-seed effect; the synthetic diagnostic showed that augmentation reduces local action sensitivity at fixed expert states, while the alignment and action-head diagnostics showed that early action error and learned representation quality remain limiting factors. The coverage audit found no missing relation, source-geometry, or action-phase category between source support/query, but did find task-conditioned phase shifts and no target-relative geometry observable within the Policy boundary. The stratified diagnostic found the largest state/RGB drift in the open-container task and task-specific transport/release error patterns. The replay audits found deterministic repeated traces, stabilization sensitivity for task 3 demo 1, stable failure for task 7 demo 0 despite HDF5 success labels, first-step HDF5/current-replay divergence in all four audited demonstrations including success controls, no mismatch in the checked controller configuration or action boundary, and deterministic current-runtime regenerated trajectories. These are mechanism evidence rather than a root-cause or formal SPI claim. Protocols and results are recorded in [the causal-alignment diagnostic note](docs/libero-bc-causal-alignment-diagnostic-2026-10-22.md), [the hidden-state diagnostic note](docs/libero-bc-hidden-state-diagnostic-2026-10-22.md), [the conditional coverage audit](docs/libero-conditional-coverage-audit-2026-10-24.md), [the stratified error diagnostic](docs/libero-stratified-error-diagnostic-2026-10-25.md), [the expert replay consistency audit](docs/libero-expert-replay-consistency-audit-2026-10-25.md), [the HDF5—current replay state alignment audit](docs/libero-replay-state-alignment-audit-2026-10-25.md), [the replay semantics audit](docs/libero-replay-semantics-audit-2026-10-25.md), and [the current-runtime replay audit](docs/libero-current-runtime-replay-audit-2026-10-25.md), and [the replay input alignment audit](docs/libero-replay-input-alignment-audit-2026-10-25.md). The input-replacement sensitivity and full source-support replay feasibility audits are complete. HDF5 causal inputs are frozen as the complete offline BC protocol; current-runtime inputs remain a closed-loop/alignment diagnostic because only 17/150 support demonstrations have complete prefix coverage. The phase/gripper loss diagnostic then found a small targeted phase-balanced benefit (weighted action MAE 0.11324 vs baseline 0.11593 across task 3/7 query steps), while a fixed 6x gripper loss worsened overall action MAE to 0.13180. The capacity-matched phase-balanced CNN-only/CNN+GRU comparison then measured weighted action MAE 0.10707 vs 0.11324; GRU had only a local task-7 transport-gripper advantage, so no stable memory benefit is claimed. The CNN-only phase-balanced extension to all five source tasks and two seeds then produced weighted query action MAE 0.12295 across 25,238 steps, with similar seed aggregates (0.12329 and 0.12261) but higher error on task 0 (0.15848). Its matched uniform-loss control was better overall (0.11708): phase balancing improved release action MAE (0.18487 to 0.16041) but worsened transport (0.12186 to 0.13935), so uniform loss remains the general baseline. These remain offline mechanism results, not SPI qualification. The next diagnostic evaluates the uniform CNN-only Policy in current-runtime closed-loop candidate-nonregression states. None of these checks is an SPT/FOMAML comparison or Module qualification. Historical controlled-environment and Crafter materials are preserved in the [archive](docs/archive/README.md). The robotics benchmark survey is in [robotic manipulation and continual task streams](docs/literature/robotic-manipulation-continual-task-streams-2026-10-20.md).

The paired phase-loss protocol and results are detailed in [the CNN-only uniform vs phase-balanced diagnostic](docs/libero-cnn-only-phase-loss-paired-diagnostic-2026-10-25.md). Both paired arms weight all seven action dimensions equally; the configured `gripper_action_weight=6.0` is unused by these loss modes and applies only to the separate gripper-weighted arm.
